# 界面坐标表（设计基准 1440 × 3168）

`BoardView` 按此表绘制，缩放系数 = min(屏宽/1440, 屏高/3168)，水平居中。

## 栅格

```
栏距 M = 50      沟槽 G = 40      列宽 W = 305
C1  50..355     C2 395..700     C3 740..1045     C4 1085..1390

① 状态条    y    0..240     开 · 名称/状态 · 主题 · 设置
② 主控      y  260..1460    方向/媒体盘（C1–C3）· 切换 · 滚动条（C4）
③ 鼠标键    y 1500..1720    左 | 右（一根宽条）
④ 键盘      y 1780..2700    4 列 × 3 行，键 305 × 280
⑤ 输入条    由 MainActivity 贴底，1250 × 192
```

> v2.0 的元素是半径各异（150/129/176）的圆，斜着撒在屏幕上，没有对齐关系。
> v2.3 起全部落在栅格上 —— 这是"看起来像设计过"和"看起来像摆上去"的区别。

## 滚动条为什么是 220 宽

v1.6 是 108。位图里它只有屏幕宽的 7.5%，拇指经常搭不上去。
现在 220（15.3%），而且**整条轨道 220 × 1000 都是热区**。

还有一个更隐蔽的 bug：v1.6 的命中判定把滚动条当成圆形（半径 = 宽/2 = 54），
所以 700 高的轨道只有中间那个直径 108 的圆能点到 —— 上下两端按下去毫无反应。
这才是"有时候点不到"的真正原因，加宽只会让这个错位更明显。v2.3 已改成按矩形判定。

## 圆盘为什么占 C1–C3

方向盘的四个箭头在半径 0.60R 处，拇指以屏幕左下角为支点划弧时，
左/下两个方向正好落在弧线上。盘做大是为了让拇指"不用瞄也能按到"，
同时它必须和 C1 的左边界、C3 的右边界对齐，否则整个版面会散。
