## 已修

### 0.3 单手开关挪位置 + 弧形排布（v2.6）

**入口够不到 = 功能白做。** 「单手」原来放在顶部状态条，正常握持姿势下右手拇指根本点不到，
还得用另一只手去点 —— 那就违背了单手模式的初衷。现在：

- 全屏模式：「单手」固定在**右下角**（设计坐标 1320, 2790，直径 180），拇指根部直接够到
- 单手模式：它压在**面板的右下角**（1000×1480 坐标系里的 915, 1380）

**圆盘上移**：单手面板从 0.50 屏高加到 0.56（`COMPACT_H` 1480→1720），
锚点仍在右下角，于是标题行和圆盘整体上移约 180px，不再挤着下面那条弧。

**弧形排布（第二版，按 Flyme 的思路）**：以右下角「单手」键为圆心、半径 520 向内画弧，
三个键按 75° / 45° / 15° 摆放：

```
单手键 (915,1620)
   ↑ 半径 520
左键 (413,1485)   ← 75°，最靠左、最低
右键 (547,1252)   ← 45°
定中 (780,1118)   ← 15°，最高
```

键放大到 250×170（换算后约 70×48dp，卡在触摸下限之上）。
第一版把中键排在最低点、右端反而更低，方向是反的；第二版又只有 54×36dp，偏小 —— 都已纠正。
单手模式下不再放拖拽 / 中键 / 左右分割条。

### 0.2 单手模式 + 定中改锁定（v2.5）

**为什么不用系统单手模式**：OPPO/vivo 那类单手模式是把整屏等比缩到角落 ——
系统改不了别人的布局，只能整体缩放。缩到 0.62 之后按键也跟着变小，而且原本铺满
全屏的坐标表缩完仍然停在"整屏"的位置关系里，拇指照样够不到远处。

**软件内自己做**：`BoardLayout.compact()` 是一套独立坐标系（1000 × 1250），
`BoardView` 把它整体缩放后贴到**右下角**，面板外压暗，看起来就是一块"迷你控制台"。

- 入口：状态条上的「单手」键（id 201），一点切换，选择记在 prefs
- 单手模式保留：开 / 状态 / 单手 / 设置 / 圆盘 / 滚动条 / 左·右 / 拖拽 / 中键 / 定中
- 单手模式收起：Esc、回车、复制、粘贴、撤销、自定 1–4（这些在单手场景下用不上，
  而且它们占的正是够不到的那片区域）
- 面板底部留出 10% 屏高的空位，避免被输入条压住

**定中改成锁定式**：原来按住才生效（clutch 跟随手指），现在按一下锁定、再按一下解除，
锁定期间键面保持琥珀色。`onResume` 时自动解除，避免回到 App 发现鼠标不动。

> 注意：这一版只完成到「编译通过」，真机截图时手机从 USB 掉线了，
> 单手模式的实际观感还需要在设备上过一眼。

### 0.1 给「小白」补的文案与信息（v2.4）

用户反馈：这套东西是给不懂技术的人用的，界面上的话得能看懂，地址得有人告诉他。

- **电脑端显示本机 IP**：状态区第二行固定显示「本机 IP 192.168.1.x」；
  未连接时第三行写「没连上手机时，手机上『手动填 IP』就填这个地址」；
  连上后第三行变成「已连接手机 PJD110 · 192.168.1.101」。
- **本机 IP 怎么选**：这台机器同时有以太网 192.168.1.100、utun8 172.31.x、vgate0 172.30.x
  等一堆地址。取「第一个非回环地址」会拿到虚拟网卡，所以按私网段优先级挑：
  192.168 &gt; 10. &gt; 172. &gt; 其它（`PcReceiver.localIpv4()`）。
- **引导面板去术语**：标题「还没连上电脑」→「无法找到我的电脑」；
  第四条「电脑防火墙拦住了 UDP 51234」→「电脑的安全软件把它拦住了」；
  正文从「连上之前……从上到下看一眼」改成「按下面的顺序看一眼，多半就是其中之一」。
- **手机端名号放大**：顶部「手机空中鼠标」从 46 放大到 62 设计单位，状态行 26→30。
- **底部输入条修版**：原来「发送」按钮的右下角被输入条两端的圆角切掉、文字贴着弧线起排。
  现在条高 192→220，左内边距 18→26dp，按钮 76×44 → 96×48dp，圆角改 24dp。

### 0. 手机上永远连不上电脑（v2.3）

**不是网络问题。** 现场实测：手机（192.168.1.101/24）→ 电脑（192.168.1.100/24）
单播 `ping from-phone` 立刻收到 `pong from-phone`；广播自动发现也通。
防火墙对 `新版本\PhoneMouse\PhoneMouse.exe` 已有 UDP 放行规则，网络类别是「公用」正好匹配。

真因是**时序 + 没有重试入口**：

- v1.6 只在 `onCreate` 里找 6 次（每次 2.5s 超时 + 3s 间隔，约 20 秒），之后再也不找
- 主界面没有「重新查找」的按钮（旧版卡片界面有，改成整屏自绘之后就丢了）
- 于是「先开手机、后开电脑」= 永远显示未连接，只有杀掉 App 重开才行

修法：

1. 连不上时每 5 秒自动重试，连上即停（`MainActivity.retryTick`）
2. 连续失败 3 次（约 15 秒）后，弹出一个**盖住整个按键区**的引导面板
   （没连上时圆盘和按键本来就都是死的，挡住不影响使用；顶部状态条留出来，
   还能进「设置」改端口）
3. 面板里按从高到低的顺序列出四个常见原因：Wi-Fi 没开 / 不在同一个 Wi-Fi /
   电脑端没运行 / 防火墙拦了 UDP 51234，并给出判断标准（电脑端灯变琥珀色）
4. 面板底部两条出路：**重新查找**、**手动填 IP**（填 IP + 端口直连，先单播 ping 验通才认，
   成功后自动收面板、关对话框）
5. 广播同时打 `255.255.255.255` 和本网段定向广播（如 `192.168.1.255`），
   避开某些 AP 不转发有限广播的情况

验证方式（可复现）：关掉电脑端 → 打开手机 App → 约 20 秒后弹引导面板 →
再启动电脑端 → **不碰手机**，桌面端起来后 5 秒内自动连上，面板与对话框一起消失。

### 1. `pong` 回复被蓝牙串口劫持（v2.1）

- **现象**：局域网里手机发 `ping` 广播，电脑收得到，但手机永远收不到 `pong` → 显示「未连接」。
- **原因**：v1.6 的 `ping` 分支是「串口优先」——`serialOut != null` 就写串口，UDP 直接不回了。
  这台机器上 `COM3`/`COM4` 是「蓝牙链接上的标准串行」，程序一启动就打开 COM3，
  于是只要蓝牙 SPP 口能打开，UDP 发现就必然失效。
- **修法**：从哪条链路来、就从哪条链路回。
- **注意**：这可能就是「有时要重试好几次才连上」的真正原因 —— 取决于那一刻 COM3 能不能被独占打开。

### 5. `Esc` 其实没走 `KeySend.exe`

`HANDOVER.md` 说 Esc 用 SendInput（KeySend.exe），但代码里 `case 7` 走的是 `Robot` 组合键。
`KeySend.exe` 在 v1.6 里**根本没有被调用过**（`sendKeyScan` / `sendKeyExternal` 是死方法）。
现状保留：Esc 继续走 Robot（实测可用），KeySend 的能力留在 `KeyInjector` 里备用。

### 6. 日志导出写死在 `%USERPROFILE%\Desktop`

这台机器的桌面被重定向到了 `D:\Desktop`，但代码用的是
`System.getProperty("user.home") + "\Desktop"`，实际写进了 `C:\Users\<你>\Desktop`。
用户会找不到文件。计划 v2.2 改成读取真实的桌面路径（注册表 `Shell Folders\Desktop`
或 `SHGetKnownFolderPath`，退回 `user.home`）。

## 待定（需要用户拍板）

### A. 蓝牙串口要不要默认自动连？

现状：启动就扫注册表找 COM 口，找到就 `mode COMx: BAUD=115200` 并独占打开。
副作用：
- 会占用用户的蓝牙 SPP 口，可能与其他蓝牙串口工具冲突
- 打开后有个线程阻塞在 `raf.read()` 上
- `HANDOVER.md` 明确说「当前版本没用到」

建议：默认不自动连，留个开关（或 `-Dphonemouse.serial=1`）。

### B. 自定义键配置文件位置

v1.6 写在工作目录 → jpackage 后大概率存不住。已改为 `%LOCALAPPDATA%\PhoneMouse\buttons.properties`，
并兼容读取旧位置、首次读到自动迁移。（已实施，告知一下）

### C. 多显示器下的光标钳制

`MouseMover.moveRelative` 按主屏尺寸钳制，副屏（尤其是主屏左侧/上侧的副屏）上光标会被挡住。
修法：遍历 `GraphicsEnvironment.getScreenDevices()` 取并集。等 v2.2 处理。

## v2.2–v2.4 实施中改掉/删掉的东西

### 删掉 🎤 按钮（手机端）

它做的事和点输入框完全一样（只是打开键盘），语音输入并没有实现。
一个不兑现的图标比少一个按钮更糟。

### 删掉「左手模式」开关（设置页）

v1.6 里它只把 `leftHanded` 写进 preferences，**全项目没有任何代码读它**。
做左手镜像要真的镜像布局，是独立功能，不该用一个假开关占位。

### 删掉不可达的「收起」分支

`MainActivity.onBoardKey` 有 `case 106: board.toggleCluster()`，
但元素表里从来没有 id 106，这个分支永远点不到。`BoardView.toggleCluster()` 保留为空方法，
只是为了不改动 `onBoardKey` 的其它分支。

### 手机端状态栏/导航栏跟随主题

`applyTheme()` 里同步 `setStatusBarColor` / `setNavigationBarColor` 与
`SYSTEM_UI_FLAG_LIGHT_STATUS_BAR`；manifest 主题从 `Theme.Material.Light.NoActionBar`
换成 `Theme.Material.NoActionBar`，否则下拉通知栏、光标、默认控件还是浅色的。

### 等宽字体不能用 Consolas（电脑端）

`Consolas` 没有中文字形，`未测`、日志里的中文会变成方块。
改用逻辑等宽 `Font.MONOSPACED`（拉丁等宽 + 复合字体回退）。

### 开关的拇指颜色要跟着状态走

只设一个 `thumbTintList` 会让「关」也是强调色，看起来像全开着。
改成 `ColorStateList`：开 = `LIVE`，关 = `INK_DIM`。
