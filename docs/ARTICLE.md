# 我做了个「手机空中鼠标」，顺便聊聊陀螺仪漂移这件小事

> 一个自用的小工具：躺床上、连电视、做演示的时候，手机当电脑的空中鼠标。
> 开源地址见文末。这篇主要是把过程中踩的坑记下来，尤其是传感器那部分。

## 为什么不用现成的

KDE Connect、Remote Mouse 这类工具我用了很久，它们做的是「触控板」——
手指在屏幕上滑，光标跟着动。

但我要的场景是**躺着**：手机在手里，屏幕朝上，我根本看不见它在哪、手指也没法精确滑。
我想要的是「手机往右转一点，光标往右走一点」，像挥一根魔杖。

所以做了两件事：倾斜控光标 + 一块给拇指用的按键面板。走局域网 UDP，不经服务器。

## 陀螺仪的坑：四种做法，前三种都失败

一开始我以为这是个简单的活：读陀螺仪角速度，乘个系数，累加。

**v0：倾角映射速度。** 手机倾斜多少度，光标就按比例移动。
结果手机平放在桌上，光标自己往右下角狂奔——陀螺仪有零偏（静止时读数不是 0），
这个零偏被当成"你在转"，然后积分起来就是无限远。

**v1：增量式 + 固定阈值。** 改成积分角速度增量，静止时用 2°/s 的阈值滤掉。
问题：这颗陀螺的零偏实测能到 3~5°/s，比阈值还大。于是永远在动，永远不校准。

**v2：30 帧滑动平均当零偏。** 平均能压住噪声。但手在动的时候，平均值把
真实转动也混进去了——你转一下手机，零偏估计就被污染，松手后光标自己飘。

**v3：48 帧中位数 + 极差判定。** 中位数不怕离群值，再用「最大值-最小值 < 3°」
判断这一段是不是静止的。听起来对，但手抖让极差轻易超标，判定一直是"在动"，
零偏永远不更新，于是温漂一点点累积。

**v4：200 帧中位数 + 分位差 + 三点中值滤波（现在这版）。**

三个改动各自解决一个具体问题：

| 改动 | 解决什么 |
|---|---|
| 窗口 200 帧（约 2 秒） | 足够长，热漂移能被持续跟踪 |
| 用 **P90-P10 < 8°** 代替极差 | 手抖是零均值的，一两个尖峰不会顶穿分位差；极差会被单个尖峰毁掉 |
| 3 点中值滤波 | 单帧尖峰会把光标甩出去，中值滤波正好干掉它 |
| 软门限 2.5~7°/s | 手抖（<2.5）完全不动，快转（>7）全速，中间线性过渡 |

结果是**静止 20 秒、0 个位移包**。这个我做了个可复现的测试：手机放桌上，
开空中鼠标，看电脑端收到多少个 `mv` 包——必须是 0。

> 这一段代码我在仓库里用 `// SENSOR-CORE-BEGIN/END` 标出来了，附了 SHA256 指纹，
> 意思就是「别乱动，动之前先跑静止测试」。

## 另一个坑：光标抖动 vs 延迟

以 60Hz 发位移包，电脑端如果每包都调一次 `Robot.mouseMove`，一次要 1~5ms，
排队就会积压——表现是「你往左按了，它还在补往右」。

最后改成：手机端累加位移，电脑端每 8ms 把累计值一次性应用，单次限幅 ±200px。
**永远只跟最新位置，不补历史。**

## UI：为什么最后做成了「仪器面板」

第一版是那种满大街的渐变卡片风——蓝紫渐变头图、圆角白卡片、等宽大按钮。
自己能跑，但看着像模板。

后来想清楚一件事：**这个软件的绝大多数使用场景是关灯的卧室。**
亮色界面在这个场景里就是手电筒。所以整个换成深色，只留一个琥珀色强调色，
只在「通着 / 刚按下」的时候出现。

还有个更实际的发现：界面上「别扭」的根源往往不是配色，而是**没有对齐关系**。
第一版所有按钮是半径各异（150/129/176）的圆，斜着撒在屏幕上，彼此毫无关联。
重排成 4 列栅格 + 四条横带之后就顺眼了。

## 单手模式：系统方案不够用

OPPO / vivo 都有系统级单手模式，但那是把整屏等比缩到角落——系统改不了别人的布局，
只能整体缩放。缩到 0.62 之后按键也跟着变小，而且那套"铺满全屏"的位置关系还在，
拇指够不到的地方照样够不到。

我们自己的 App 能重排，所以做了一套独立坐标系：整套面板缩到右下角，
只留 8 个键，按键沿**拇指划弧**的方向排——以「单手」键为圆心画弧，
越往左角度越大、位置越低。

中间排错两次：第一版把中键放在最低点（方向反了），第二版按键只有 54×36dp（小于
48dp 触摸下限，手指会点空）。这两个错误按坐标推算都看不出来，只有截图才暴露。

## 一个很隐蔽的 bug

滚动条「有时候点不到」。查下来：命中判定把它当**圆形**算（半径 = 宽/2），
于是 700 高的轨道只有中间那个直径 108 的圆能响应，上下两端按下去毫无反应。

同类问题还有：UDP 发现被蓝牙串口劫持——只要蓝牙 SPP 口能打开，`pong` 就写到串口去，
局域网发现永远收不到回包。表现是「有时候要重试好几次才连上」。

两个都是同一类错误：**默认了数据结构是简单的，没有按真实形状判定。**

## 做到一半才想明白的事

- 用户（包括我自己）看不懂「防火墙拦住了 UDP 51234」。改成「电脑的安全软件把它拦住了」，
  后面接「重新查找 / 手动填 IP」两个按钮，才是他需要的东西。
- 电脑端必须显示**自己的 IP**。因为手机上「手动填 IP」要填的就是它，而小白不知道去哪看。
- 没连上时那套按键是死的，所以引导面板可以直接盖住整屏，不用怕挡。

## 状态

两端都能跑，实机验证过。协议没做鉴权，只适合可信局域网（自己家、手机热点），
这个在 README 里写得很显眼。

下一步想做的是：协议加共享 token、蓝牙直连（接语音输入）。
传感器那 168 行还赖在主 Activity 里没搬出去，等哪天有空再说——**能跑就别动**。
